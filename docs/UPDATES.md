# Обновления Бабуина через GitHub Releases

## Что изменилось

- Путь: Настройки -> Обновления. Также при запуске приложения проверяется новая стабильная версия.
- APK скачивается во внутренний cache/updates, не в Download.
- SHA-256 из релизного `.sha256` сверяется в Kotlin перед запуском системного установщика.
- Android обязательно спрашивает разрешение на установку из Бабуина и подтверждение обновления.
- Релизы публикуются только вручную через `Actions > Build APK > Run workflow`.
- Flutter Bootstrap больше не запускается.

## ОДИН РАЗ: создать постоянную подпись (в Termux, не во время работы Qwen)

Используйте свой собственный пароль и обязательно сохраните keystore вне телефона.
Установите Java, если `keytool` отсутствует:

```bash
pkg install openjdk-17
```

Создайте ключ (введённый пароль вводить самостоятельно, без отправки в чат):

```bash
keytool -genkeypair -v -storetype PKCS12 -keystore baboon-release.p12 -alias baboon -keyalg RSA -keysize 3072 -validity 10000 -dname "CN=Baboon, OU=Personal, O=Baboon"
```

Затем закодируйте файл для GitHub Secret:

```bash
base64 -w 0 baboon-release.p12 > baboon-keystore-base64.txt
```

Если в Termux `base64 -w 0` недоступно, используйте:

```bash
base64 baboon-release.p12 | tr -d '\n' > baboon-keystore-base64.txt
```

В репозитории: `Settings > Secrets and variables > Actions > New repository secret`.

Добавьте **три** секрета:

- `BABOON_KEYSTORE_BASE64`: одна длинная строка из `baboon-keystore-base64.txt`.
- `BABOON_STORE_PASSWORD`: пароль, введённый при создании ключа.
- `BABOON_KEY_PASSWORD`: тот же пароль (для PKCS12).

Не добавляйте `.p12`, пароль или base64 в публичный репозиторий и не отправляйте их в чат.
Сделайте **резервную копию** `baboon-release.p12` и храните пароль отдельно.

## Первое переключение подписи: ВАЖНО

Старый APK собран с *debug-подписью*, новая версия — с постоянной. Из-за этого Android может отказаться обновить старую установку поверх неё. Тогда будет нужна **одна последняя переустановка**.

До удаления старого приложения:
- Убедитесь, что копия GGUF есть в Download или другом надёжном месте.
- Сохраните важные переписки вручную: текущая версия не содержит надёжного экспорта всех данных.
- Учтите: удаление приложения стирает **приватные** файлы GGUF и переписки в его каталоге.

После перехода на постоянную подпись дальнейшие сборки с тем же ключом устанавливаются поверх приложения без удаления данных, пока `applicationId` неизменен и номер сборки растёт.

## Проверка

1. Добавить эти файлы в репозиторий и три Secrets.
2. Запустить Build APK вручную.
3. Проверить, что новый релиз НЕ `Pre-release`, есть APK и файл `.apk.sha256`.
4. Установить новую сборку (один раз может потребоваться переустановка старой).
5. Запустить следующую ручную сборку.
6. Открыть Настройки -> Обновления и проверить, что обновление предлагается и ставится поверх существующего приложения.

Если версия из Releases старее уже установленной, кнопка скачивания не появляется.
