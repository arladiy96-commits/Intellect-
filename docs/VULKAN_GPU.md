# БАБУИН — Vulkan GPU (эксперимент)

## Что изменено

- Android arm64 собирает `llama.cpp` (закреплённый commit `f2f667b02dc76d675395ae3b14546c8108d26387`) с `GGML_VULKAN=ON` и с сохранением CPU.
- GitHub **ручной** Build APK устанавливает glslc, libvulkan-dev и spirv-headers на runner. Android SDK/NDK, подпись ключом BABOON_*, публикация APK в GitHub Releases сохранены. Автоматической сборки нет.
- GPU-переключатели в `Модели`: CPU = 0 слоёв, гибрид = 8/16/32 GPU-слоя, GPU макс. = 99 слоёв. Изменение требует выгрузить модель, затем загрузить заново.
- `llama.cpp` определяет устройство Vulkan по ggml backend; если оно недоступно или загрузка отклонена, приложение пытается загрузить модель в CPU-режиме и сообщает о fallback.
- В случае гибели процесса при загрузке GPU **или во время генерации** режим при следующем запуске автоматически сбрасывается на CPU. Это не делает GPU-драйверы полностью безопасными и не исключает принудительного закрытия процесса Android.
- Память, переписки, GGUF и ключи подписи не удаляются. Повторный импорт модели не требуется при установке APK поверх прежней, подписанной тем же ключом.

## Первая проверка на POCO X8 Pro Max

1. Обновить установленную APK поверх прежней (не удалять приложение!).
2. `Модели` → выгрузить Qwen 9B, если загружена; выбрать CPU и загрузить 4B. Сохранить исходную скорость: ~5 токенов/с.
3. Выгрузить 4B → переключиться на `GPU 8` → загрузить 4B.
4. В **новом пустом чате** задать одинаковый вопрос, например «Напиши три коротких предложения про осень». Дождаться завершения и сравнить `скорость`, `подготовку`, `весь ответ`.
5. Если GPU 8 стабилен, попробовать GPU 16, затем 32. Только после этого — GPU макс. (99). В любом режиме GPU может быть медленнее CPU.
6. 9B пробовать только после успешных тестов 4B и с 8 слоями для начала. Не тестировать горячий телефон и не делать длительных тестов на зарядке.

## Что может не сработать

- Vulkan на GPU MediaTek/Immortalis зависит от устройства и драйверов; производительность **не гарантируется**.
- Нужен полноценный NDK Vulkan SDK/компилятор shaders и native упаковка библиотек в APK. В случае ошибки GitHub Actions нужны логи этапа (важнее всего Gradle/CMake).
- Это только GPU offload и простые измерения. **Кэширование KV-контекста не реализовано**. Оно требует отдельной корректной обработки chat template, позиций токенов, состояния sampler и переключений чатов.

## Файлы

1. `.github/workflows/build-apk.yml` — добавить пакеты shader tools в прежнюю **ручную** сборку.
2. `android/app/src/main/cpp/CMakeLists.txt` — Vulkan backend и NDK linking.
3. `android/app/src/main/cpp/llama_bridge.cpp` — `n_gpu_layers`, GPU detection, CPU fallback signals.
4. `android/app/src/main/kotlin/ai/moy/moy_ai/LocalLlamaBridge.kt` — новые JNI методы.
5. `android/app/src/main/kotlin/ai/moy/moy_ai/MainActivity.kt` — настройки GPU, fallback, защита от повторных GPU-crash.
6. `lib/src/core/ai/llama_native_engine.dart` — состояние настроек и статусы.
7. `lib/src/features/models/models_screen.dart` — выбор режима, уведомления и измерения.

### Техническое предупреждение

Новая версия требует **проверки GitHub Actions и испытания на самом телефоне**. На этой стадии не утверждается, что Vulkan уже собирается или работает на устройстве. Изменения не затрагивают root, прошивку, напряжение или частоты чипа.
